Bytecode Analysis Engine — Service Implementation

Server-side implementation of the {@link au.net.zeus.jgdms.api.codebase.BytecodeAnalysisEngine} (BAE) service. Code in this package runs inside the BAE Phoenix activation group and must not appear on the service codebase.

{@link au.net.zeus.jgdms.bae.BytecodeAnalysisEngineImpl}

The non-activatable implementation of the BAE service. Extends {@link au.net.zeus.jgdms.service.support.AbstractJiniService} and provides the core {@code containsDangerousCode()} analysis logic:

  • Scans bytecode for reflective invocations ({@code Method.invoke}, {@code Constructor.newInstance}), object-graph construction ({@code ObjectInputStream.readObject}, {@code Unsafe.allocateInstance}), and process-execution calls ({@code Runtime.exec}, {@code ProcessBuilder.start}).
  • Provides a canonical byte-array helper that sorts and deduplicates evidence entries before signing, ensuring deterministic signatures across BAE instances.

{@link au.net.zeus.jgdms.bae.ActivatableBytecodeAnalysisEngineImpl}

Phoenix-activatable variant of the BAE service. Wraps {@code BytecodeAnalysisEngineImpl} with the standard JGDMS activatable lifecycle and is started by an activation descriptor rather than {@link net.jini.config.Configuration} directly.

Security model

The BAE must be deployed in a dedicated Phoenix activation group with a restrictive security policy. In particular:

  • The BAE must not hold the VR's signing key-pair.
  • Outbound network connections are restricted to codebase HTTP(S) servers only; the BAE must not be able to reach clients or the VR directly.
  • Write-back to external services is prohibited.
