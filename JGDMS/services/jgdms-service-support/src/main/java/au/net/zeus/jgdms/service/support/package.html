Abstract Jini Service Infrastructure

Reusable server-side base classes for building Jini services. Code in this package runs only in the service JVM and must not appear on the service codebase.

{@link au.net.zeus.jgdms.service.support.JiniServiceParameters}

Abstract parameter object whose constructor reads and validates all common Jini service configuration entries from a {@link net.jini.config.Configuration}:

  • Mandatory: {@code exporter}, lookup {@code groups} / {@code locators} / {@code attributes}, and codebase fields ({@code certFactoryType}, {@code certPathEncoding}, {@code encodedCerts}).
  • Optional: {@code loginContext} (type {@link javax.security.auth.login.LoginContext}, default {@code null}) and {@code persistenceDirectory} (type {@link java.lang.String}, default {@code null}).

A {@link net.jini.config.ConfigurationException} is thrown immediately if any mandatory entry is missing or has the wrong type, so service constructors always receive a fully-validated parameter object. Service-specific subclasses add their own mandatory entries in the same way.

{@link au.net.zeus.jgdms.service.support.AbstractJiniService}

Abstract base class providing the complete Jini service lifecycle. Implements {@link net.jini.admin.JoinAdmin}, {@link org.apache.river.admin.DestroyAdmin}, and {@link java.rmi.Remote} directly so that every exported server stub automatically carries the admin interfaces without requiring a combined marker interface.

The {@code start()} method is {@code final} and performs, in order:

  1. Export the service via the configured {@link net.jini.export.Exporter}.
  2. Call the protected {@code onExported()} hook.
  3. Recover persistent state (if a {@code persistenceDirectory} was configured) or generate a fresh {@link net.jini.core.lookup.ServiceID}.
  4. Create the smart proxy via {@code createProxy()}.
  5. Start a {@link net.jini.lookup.JoinManager} to advertise in all configured lookup services.
  6. Call the protected {@code onStart(Subject)} hook inside the login {@link javax.security.auth.Subject}'s security context (or with {@code null} when no login context is configured), allowing subclasses to initialise Subject-aware thread pools or executors.
  7. Transition to the ready state.

When a {@code loginContext} is configured, {@code start()} calls {@link javax.security.auth.login.LoginContext#login()} and wraps the entire start sequence in {@link javax.security.auth.Subject#doAsPrivileged(Subject, PrivilegedExceptionAction, AccessControlContext)}, mirroring the pattern used by {@code FiddlerImpl} and {@code MailboxImpl}.

Persistence

When {@code persistenceDirectory} is non-null, service state is persisted using {@code org.apache.river.reliableLog.ReliableLog} — the same write-ahead log used by existing Jini services such as Reggie (Service Registrar / Lookup Service), Fiddler (Discovery Service to find Lookup Services), Mahalo (Transaction Service), Mercury (Event Mailbox Service), Norm (Lease Renewal Service) and Outrigger (Javaspaces). The {@code ServiceID} is stored in every snapshot and recovered on restart so the service re-advertises under its original identity. Subclasses may override the protected template methods {@code snapshot(ObjectOutputStream)}, {@code recover(ObjectInputStream)}, and {@code applyUpdate(Object)} to persist service-specific state alongside the {@code ServiceID}. Incremental state changes can be recorded between snapshots using the protected {@code logUpdate(Object)} utility.

Administration

{@code getAdmin()} returns an {@link au.net.zeus.jgdms.proxy.AdminProxy} (or its inner {@code ConstrainableAdminProxy} variant) backed by the exported server stub. Service developers do not need to implement any administration logic; it is all handled by the base class.
