| 2 | 2026-11-21 | Treat clients and services written in other languages (Rust and Haskell were the two discussed) as a design constraint on the DER wire. Where the client is compiled against the service interface, a forwarding proxy generated at build time from a published interface schema does what a Java dynamic proxy does; what arrives at run time is data only (endpoint, object identifier, constraints, and a digest of the interface schema to prove the interface matches). Clients that do not know the interface use an untyped call that reads the interface description from the wire. Not checked: how much of the DER wire still assumes Java. Places to look: any type named by Java class name instead of a schema digest; how a remote exception is carried back; objects that are themselves proxies (leases, event registrations, transaction participants); how method constraints are expressed to a client with no constraint classes.
