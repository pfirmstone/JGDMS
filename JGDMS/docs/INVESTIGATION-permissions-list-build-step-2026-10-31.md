## 2. The change (uncommitted)

`JGDMS/pom.xml` +94 lines, no deletions (the root parent of all 10 -dl modules; no -dl pom touched): two profiles in `<profiles>` plus a comment. `JGDMS/check-permissions-list-in-jar.sh` (new, 192 lines, md5 55d1b486ae63, beside the existing `check-*.sh`). This file.
- `proxy-permissions-list-generated`: active when `-Dpermissions.list.generated.dir=<dir>` is given AND the module has no `${basedir}/src/main/resources/META-INF/PERMISSIONS.LIST`. Runs `resources:copy-resources` at `process-resources`: from `<dir>/${project.build.finalName}/META-INF`, include exactly `PERMISSIONS.LIST`, no filtering, into `target/classes/META-INF`.
- `proxy-permissions-list-generated-wins`: active on `-Dpermissions.list.generated.wins=true`; the same copy with `overwrite` (it runs after `default-resources`), so the generated file replaces a checked-in one.
- `<dir>` is a generator output directory; the artefact subdirectory is named like the jar (`mahalo-dl-4.0.0-SNAPSHOT`, which is what the generator emits for a `lib-dl/*.jar` codebase).
- Use: `mvn -o -pl <modules> -am package -Dpermissions.list.generated.dir=C:/.../qa/harness/policy/<policy>.proxy-permissions`.
- **Why Maven, not Ant:** the same lifecycle that builds the jar, offline, no new plugin (maven-resources-plugin 3.3.1 is already pinned in this pom); profile activation states "checked-in wins" declaratively, where Ant would need conditional script logic in a second build system that does not run for a plain `mvn package`. One edit in the common parent, not ten. Not tested: an unconditional extra `<resource>` entry; I did not try it, so I make no claim about its copy order.
- **Constraints:** (a) VERIFIED: three no-file cases all build, rc 0. (b) VERIFIED: checked-in bytes win; override needs the explicit property. (c) VERIFIED: with no property both jars are byte-identical to the [A] jars. (d) VERIFIED: exactly one entry named `META-INF/PERMISSIONS.LIST`, none else with PERMISSIONS in the name. (e) Maven.
